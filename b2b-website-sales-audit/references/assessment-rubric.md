# 评估判据：沿买家的决策过程判断

开始抽样前读取。用来解释网站能否支撑采购，不是机械打分表。

## 状态与证据覆盖

| 状态 | 适用条件 |
|---|---|
| 基础良好 | 核心样本能支持该采购步骤，未发现明显阻碍；必须说明检查到的范围，不等于全站无问题 |
| 有改善空间 | 路径可用，但有已观察的信息/证据/意图匹配缺口，说明实际缺的是什么 |
| 明显障碍 | 观察到直接阻断或严重误导核心路径的现象，并得到足够复核，如证书错误、关键路径死链、国家选项限制 |
| 未验证 | 未取得足够证据、工具失败、样本不适用或结果冲突尚未解决；不折算成差评 |

信心单独标高/中/低：直接页面或可重复观察支持的具体事实较高；不完整抽样和间接信号较低。可信的单页事实仍不代表可信的全站结论。

给获客、SEO、GEO各一行状态与依据，GEO的准备度和实测另分两行。任何一个维度出现严重问题不自动压低其他维度。行业不适用项写N/A，不扣分。

## 1. 获客承接

| 检查 | 观察什么 | 商业含义与边界 |
|---|---|---|
| 角色与定位 | 产品/服务、买家、使用场景、企业角色是否清楚 | 泛泛口号不足以帮助初筛；贸易公司无需冒充工厂，软件公司也不需要工厂照片 |
| 初筛信息 | 采购方是否能判断适配性与下一步 | 物理产品看真实规格、配套、定制/起订/交期条件；软件看功能边界、部署/集成、安全与演示；项目服务看范围、流程、案例和报价所需输入 |
| 可信证据 | 名称地址、证书主体/范围、项目案例、检测/质检、团队/交付能力 | 没公开证书不等于没证书；没客户Logo不等于没客户；不能从公司自述独立验证产能 |
| 行动入口 | 类别/详情到询价、索样、咨询、预约演示的实际路径 | CTA词弱只是线索，要检查是否真的造成下一步不明确；不机械要求统一按钮文案 |
| 联系负担 | 字段、星号、国家/电话限制、验证码、附件或产品上下文 | 标记必填与实际服务端校验分开；不提交即不能声称提交失败或收件正常 |
| 设备可用性 | 核心路径在手机布局中能否阅读、选择和联系 | 桌面截图不证明移动端通过；工具模拟也不等于真实设备全覆盖 |
| 接收和归因 | 只能观察到入口/脚本还是有客户提供的成功记录 | 点击联系不等于询盘，询盘不等于合格线索；看不到GA脚本不等于无统计 |

同一企业可能兼有制造、贸易和定制业务。先准确说明“官网怎么描述”，把资产关系和资质问题留给业务核实。

询盘判断直接使用上表，不依赖其他私有 Skill。不机械要求 WhatsApp、固定回复时限、工厂照片或客户 Logo；以实际买家、经营角色和可核查证据判断。

## 2. SEO

| 检查 | 有价值的判断 | 避免的误判 |
|---|---|---|
| 访问 | HTTPS、HTTP状态、www/裸域的实际跳转及关键页可达性 | 单个抓取工具失败不能证明全球不可用；robots 404不是禁止抓取 |
| 主域 | 品牌、联系信息、canonical、重定向、手机/语言域是否一致 | canonical指向别域可为正确规范化，不能直接说抢排名或权重泄露 |
| 发现 | 分类/产品href、页面层级、已发现sitemap、noindex | javascript组件存在不等于全站不可抓；常见地图路径404不等于没有其他地图 |
| 意图匹配 | 搜索结果期待的页型与现有页面是否一致，是否有真实采购正文 | 型号标题未必无价值；不能为SEO杜撰容量/用途；字少不自动是差内容 |
| 可见性 | 具体品牌与采购查询中出现的页面、位置、市场和日期 | site结果不是全站索引量；数据库没有记录不是没有排名；样本未出现不是无任何流量 |
| 同业对照 | 同样客户/品类/市场的页面提供了什么有用采购信息 | 有竞争页面不能推出它抢走了多少订单；高DR不等于业务匹配 |

只有取得真实性能数据才报速度/Core Web Vitals数值。没有测试就不靠视觉感受报“加载慢”；没有GSC/日志不诊断确定的收录/流量损失原因。

品牌词、非品牌词分开；主品牌与旧域相关时联合观察。查询候选从官网实际业务出发，工具返回搜索量时注明市场、日期和估算口径。

## 3. GEO

### 准备度

- 企业/品牌/域名关系能否辨认，是否需要由客户解释。
- 产品和服务事实是否可读、可核对，有明确适用条件。
- 页面能否直接回答采购问题，有案例、规格、过程或数据支撑。
- 官方资料与可取得的外部资料是否一致；历史地址不同可以是搬迁，不能直接称虚假。
- 结构化数据与可见信息是否一致。Schema和llms.txt都不是保证引用的开关，缺失不单独构成严重问题。

### 平台实测记录

每份回答单独记录：

| 字段 | 判定 |
|---|---|
| 运行状态 | 成功且有可用回答 / 成功但无答案或未触发AIO / 服务报错 / 未测试 |
| 品牌提及 | 正文是否出现确认的品牌及合理别名；处理同名误匹配 |
| 官网引用 | 引用列表有无已确认官网/关联域，记录具体URL；仅正文文本域名另记 |
| 场景推荐 | 是否明确把目标企业列为适合该采购情景的候选，不把负面提及当推荐 |
| 描述准确性 | 与已核验企业事实一致、冲突或无法核实；模型自述不是真相源 |
| 可比对象 | 实际出现哪些供应商/方案与引用页面，不自行补入 |

默认用逐问题表呈现，不合成“AI市场份额”。确需给样本比例时同时列问题数、平台、成功回答分母、未触发及失败数，名称写“本轮成功回答样本命中”，不可作整体可见度。

Google AIO未触发与有回答但未提及品牌是两种状态。带品牌提问仅测品牌理解，不能拿来计算自然采购推荐。

## 4. 挑选沟通重点

优先：影响真实买家步骤、有明确证据、能落到具体页面及小范围动作。

访问/联系障碍通常优先于增加新内容；页面已成熟时关注目标市场、差异化和可测量的改进，不硬套“必须重建”。

没有硬缺陷时：展示优势 + 一个有证据的需求机会，或提出需要客户数据验证的假设。高覆盖的“暂无明显切入口”是有效结果；低覆盖的“需要补信息”不是客户表现差。
