# 从诊断转成销售沟通

写简报前读取。目的是真实确认需求、建立信任、推进适合的下一步。生成草稿不授权发送。

## 1. 沟通准备度不等于客户价值

| 标签 | 判据 | 下一步 |
|---|---|---|
| 有明确切入口 | 存在可核查且影响采购/发现的具体问题，并与我方已确认服务相关 | 带1–2条证据沟通，确认商业背景 |
| 需补业务信息 | 页面信号有解释空间，市场/主域/转化等关键信息缺失 | 先用少量具体问题确认，不带着确定诊断推销 |
| 暂无明显切入口 | 覆盖足够且关键路径表现良好，未发现与我方服务匹配的明确缺口 | 如实认可；根据客户主动提出的目标决定是否深化 |

资料少不代表客户差；网站差不代表有预算；品牌已知名不代表一定值得投入。未经客户信息，不编造销售优先级A/B/C或成交概率。

## 2. 每个沟通点的骨架

1. **业务理解**：这家公司服务哪类客户、什么采购需求；推断要有保留。
2. **观察事实**：具体页面上看到了什么，附URL/证据ID。
3. **业务含义**：这可能在哪一步增加阻力，或哪里有值得复制的优势。
4. **确认问题**：问事实发生的背景和当前业务流程，而非诱导同意“你的网站不好”。
5. **小范围下一步**：明确一次核验、一个页面样板或一次需求梳理能产出什么。

不以“你们网站很差”“AI完全找不到你”“不做就错过市场”等恐吓开场，也不借旧案例的数据声称当前客户损失。

## 3. 30秒开场

建议约100–180字，随语言调整；不是硬字数。

“我们看了贵司的[具体产品/方案]页面，[有证据的优势]已经比较清楚。检查[具体路径]时，发现[事实]；对[买家/市场]来说，这可能增加[决策或联系成本]。想先了解[一个关键业务问题]，再判断是否值得从[具体页面/流程]做一轮小范围改进。”

若没有缺陷，改为优势与验证问题，不套“发现问题”的句式。

## 4. 需求访谈：只选与发现有关的问题

- 当前希望官网带来哪类客户，最重要的产品/项目是什么？
- 客户实际集中在哪些国家/行业？网站展示范围与主要订单是否一致？
- 新客户通过表单、邮件、即时通讯、渠道商还是销售主动开发进入？
- 销售最常反复解释哪些规格、适配条件或能力？能否提前放到页面？
- 哪些资质/项目允许公开，哪些因为保密只能提供脱敏资料？
- 当前网站主域和历史域是否有商业用途？
- 对改进结果最在意的是曝光、有效询盘、报价、样品还是项目机会？

内部简报通常选3–5问，按沟通重点排序，不输出冗长的资料索取清单。预算和决策流程可以在双方确认需求后询问，不能由网站臆测。

## 5. 根据实际发现回应异议

| 客户可能说 | 可用回应的依据 |
|---|---|
| 我这里能打开 | 说明检查时间、协议和客户端，展示证据；承认可能存在地区或环境差异，提出共同复现 |
| 我们主要靠展会/老客户 | 官网也可承担客户验证与资料提供；先核实是否需要改善这一环节，不强行假设要扩大SEO |
| 网站现在有询盘 | 承认已有成效，关注询盘质量和销售反复解释的成本；没有数据不称转化差 |
| 我们已经在做SEO | 就具体页面/意图和现有团队核对，不批评已有服务商；询问现阶段目标与结果口径 |
| AI提不提我们有什么关系 | 解释只测试了哪些采购问题，评估其与真实客户行为的相关性；可以优先解决更明确的询盘问题 |
| 你们能保证排名或订单吗 | 只约定工作范围、交付、核验方式和复盘周期，不保证搜索或销售结果 |

不是每份简报都要列齐六种异议。选2–3个与该客户事实有关的回应，避免模板感。

## 6. 服务映射

从问题推服务，不能从套餐反推问题：

| 已验证的主要需求 | 可讨论的第一步 |
|---|---|
| 访问/表单/路由错误 | 小范围技术与询盘路径修复，并验证关键动作 |
| 采购资料或信任证据薄弱 | 选一个核心类别或产品做样板，补真实资料与询价承接 |
| 业务清楚但采购搜索承接不足 | 目标市场搜索意图核验 + 核心商业页规划 |
| 基础成熟且有内容缺口 | 基于销售问题建设采购指南及产品内链 |
| GEO样本显示特定发现/归属缺口 | 补实体与事实材料，固定问题复测；不默认购买媒体或榜单 |
| 数据不足或客户反馈与观测冲突 | 共同确认基线与采样，之后再决定方案 |

重建网站需要证明当前平台或架构确实妨碍实施，不能因视觉陈旧或模板重复就推荐重建。价格、服务承诺和商业条款只用本次已确认资料；未知时写“范围确认后估算”，不读取任意旧报价自动套用。

## 7. 客户摘要发布检查

- 保留已有优势、证据、业务含义、优先动作和范围说明。
- 删除沟通准备度、开场、追问策略、异议应对、内部成本、议价与售卖判断。
- 涉及我方能力只写已确认内容，不假装客户同意合作。
- 每个建议都能指向一个页面/流程或明确需验证的问题。
