# 外贸网站获客体检

让网站负责人看懂：产品卖给谁、采购方在哪一步需要更多信息或遇到障碍、证据是什么、下一步优先改哪里。

默认生成 **网站诊断摘要 + 证据底稿**。只有用户明确需要售前沟通材料时，再增加内部销售简报；两者使用同一套证据。网站的改进空间不等于客户预算、意愿或成交概率。

## 输入与范围

输入一个网站 URL 即可启动。可选信息：品牌、主营业务、目标国家/语言、已知竞品、销售阶段、我方服务范围。

- 从官网识别企业角色、买家和主要转化动作。制造商/贸易商看采购与询价；B2B软件看方案评估与预约演示；项目/专业服务看能力边界与需求咨询。先识别，再选检查项。
- 没有目标市场时，依据页面语言和明确服务范围选择一个样本市场，标明是检查假设；不将默认美国英语当企业实际市场。
- 只有缺失信息会改变评估对象或核心判断时才询问；未知流量、收入、预算不阻塞公开评估。
- 复用同一客户的已有证据，但保留采集日期。访问故障、表单、搜索与AI结果可能变化，不能把历史回放写成实时检测。
- 若是纯B2C电商或对象无法确定，说明适用边界，提供能确认的观察；不硬套B2B评分。

默认公开页面抽样，不承诺全站审计或固定运行时长。无需GSC、GA4、CRM授权；用户已有授权数据可以补充，缺失不标低分。

## 执行

首次采集前读取 [证据与工具路线](references/evidence-and-tool-routing.md)，先确定需要保留的时间、市场和来源信息。

### 1. 认清业务和域名

读取首页、About及核心产品/服务入口，写出一句业务描述，并区分官网自述与已核验事实。识别主品牌、关联域、手机域、canonical及跳转；发生域名和品牌不一致时先核查，不直接判定“权重流失”或擅选新主域。

### 2. 抽样检查获客链路

读取 [评估判据](references/assessment-rubric.md)，先看首页、一个核心类别或产品详情、联系/表单和 About；有相关内容时补一篇代表性指南或案例。首轮通常4–6页，多个业务或样本冲突会改变判断时再扩到8–12页。列明实际覆盖范围。

- 至少沿一条“需求/产品 → 详情 → 联系”实际路径检查，记录页面证据。
- 关键动态表单、菜单和CTA用浏览器确认；可做无提交的导航和下拉检查，不填写发送测试询盘。
- 有浏览器条件时查看一条核心路径的移动布局；只有桌面或HTML时明确移动体验未验证。
- 重要规格可能在图片/PDF中，不能仅因正文没有就宣称不存在。实际看不到时标未验证。
- 按获客、SEO、GEO三个维度归纳；GEO准备度与平台实测分开。

### 3. 验证搜索与 AI 发现情况

沿用采集前确认的工具路线与降级规则，只调用当前环境可用能力，不把不存在的工具写成已运行。

**SEO默认检查：** 1组明确品牌查询、2–3个与真实业务相关的非品牌采购/解决方案查询，记录引擎、地区、语言、日期、返回范围和命中页面。`site:` 只作发现线索。可用授权排名库可补样本，不必默认跑完整流量/外链/域龄分析。

**GEO可选实测：** 用户要求且当前有可用能力时， 选3个不同采购意图的无品牌问题，在至少2个当前可用、能保存完整回答的平台各查一次。问题适配经营角色；贸易企业不能只测试“自有工厂排名”。记录品牌提及、官网引用、场景推荐和描述准确性，不能互相替代。

不足3问或2平台仍交付实际结果与范围，不补造数据、不无限等待。没有可用AI查询服务时只评GEO准备度，平台表现明确“未实测”。普通SERP或模型记忆不能充当AI平台实测。

发现相关同业页面时，可读1个真正可比的落地页作具体对照；没有合适对象则省略，不为满足模板强加竞品榜单。

### 4. 建立证据，再判断优先级

按 [证据模板](assets/evidence-template.md) 保存证据ID、URL、日期、范围、观察、业务含义、可信度。原始页面、查询和必要截图放同一评估目录。

每个重点判断使用：

`观察事实 → 买家可能遇到的困难/已有优势 → 改进方向 → 要向客户核实的问题`

按业务影响、证据强度和可执行性选3–5项；不足就少写，已有优势也应保留。没有直接缺陷不等于必须制造内容问题。

维度状态仅用 **基础良好 / 有改善空间 / 明显障碍 / 未验证**，同时标记覆盖范围和信心。按评估判据判定，不合成百分制总分、不推测损失金额或成交率。

### 5. 生成网站负责人能使用的材料

默认中文交付，用户指定语言优先。需要额外内部销售简报时才读 [销售沟通规则](references/sales-conversation.md)。

使用用户指定目录；未指定时写到当前项目 `website-audits/<domain>/<date>/` 并告知位置；已有同日结果保留，复测使用新的run目录，不覆盖原始证据。

```text
<本轮目录>/
  client-brief.md       # 可发客户的诊断摘要
  sales-brief.md        # 可选：明确需要时才生成的内部销售材料
  evidence.md          # 证据索引与完整采样范围
  raw/                 # 实际取得的HTML/搜索/AI回答，不建空占位文件
  screenshots/         # 有视觉证据时才创建
```

默认使用 [诊断摘要模板](assets/client-brief-template.md)；需要时另用 [内部模板](assets/sales-brief-template.md)。报告长短服从证据，不按固定行数凑稿。默认Markdown；用户需要Word/PDF/HTML时再用环境相应文档能力转换。

客户版用业务语言解释问题，附页面链接与必要截图，不出现内部客户评级、话术、价格策略、工具成本或本地绝对路径。内部简报引用证据ID，并给销售可直接使用但**尚未发送**的沟通草稿。

不因评估而修改官网、提交表单、联系第三方、发送消息、发布报告或承诺报价。服务映射只依据用户当前确认的范围；没有可用报价依据则不写价格。

### 6. 交付前核验

- 客户、域名、经营角色、语言和抽样市场一致，没有残留前一个客户名称。
- 每个重大结论都有证据ID，能区分事实、推断与未知；单页问题没有扩大成全站问题。
- 第三方空数据未当零流量；无实测未当零AI曝光；证书或网络错误已说明请求上下文。
- GEO区分提及/引用/推荐；引用的同业页面确实读过，没有把营销自述升级为独立背书。
- 有内部简报时，两份材料的事实、数字、日期、范围一致；客户摘要没有内部销售内容。
- 网站负责人能从材料中挑出2–3个可执行的具体动作；若证据不足，则拿到的是验证问题而非伪结论。
- 记录未验证的表单送达、实际询盘转化、后台数据和设备范围，提出最小的下一步。

满足这些条件即完成本轮体检。扩大到全面审计、复杂迁移、全量竞品/关键词或长期监控，留给用户明确要求的后续任务；不自动触发完整重型审计技能。
