# 单页 GEO 内容检查

帮助产品页、商业页、采购指南与文章把已有事实讲清楚、讲准确，让读者和机器更容易理解。产物是段落级的发现与改写，不据此认定某个平台不引用的原因，也不预测引用率涨幅。

## 输入与工具

以下任一种输入即可开始：URL、粘贴正文、文本文件；可补充目标采购问题、市场和读者。

- 正文可直接审阅，无需 Key、账户文件或其他 Skill。
- URL 模式用当前环境可用的网页读取、浏览器或公开 HTTP GET。获取失败后换一种可用方式，仍失败则请用户提供正文；不无限重试。
- 只有正文时，HTML、Schema、响应头、移动交互均标“未验证”。不能从排版后的正文推断源码缺少某个标签。
- 不自动接入付费采集、读取凭证、查询 AI 平台或扩大成全站审计。需要页面技术复核时，可选使用本仓库的 page-seo-inspector。

## 检查方法

### 1. 先识别采购任务

写明页面帮助哪类读者回答什么问题。先判断页型，再判断信息是否充足：产品页看规格、条件与适配；采购指南看选择依据与权衡；商业页看业务范围、证据和下一步。不要把文章的引用格式机械套到产品参数表。

为正文段落或逻辑块编号 ¶1、¶2……，表格、列表和规格块也可作为独立单元。长文可先审关键部分，但必须写明覆盖范围。

### 2. 按信号找证据

| 信号 | 具体检查 | 判断边界 |
|---|---|---|
| 可核查事实 | 型号、材料、单位、容量、适配条件、日期、统计口径是否清楚 | 有意义的规格比泛泛口号更有用；不为提高数字密度硬加统计 |
| 来源与依据 | 核心主张是否能追溯到原始来源、测试条件或企业真实资料 | 自有规格可引用官方资料；不要求每段都有第三方链接 |
| 引语与经验 | 专家/客户原话是否真实、准确、可公开，是否说明身份与场景 | 没有引语本身不是缺陷；不编造专家、评价和授权 |
| 清晰表达 | 句子有无歧义，术语是否解释，关键词是否自然 | 句长、段长和关键词次数仅作线索，不设硬性阈值 |
| 答案组织 | 关键答案是否容易找到，段落脱离上下文后是否仍能理解 | 根据任务使用标题、列表或对比表，不强制所有标题改问句 |
| 信息完整性 | 优势是否有条件、限制、对比依据和采购下一步 | 不把“不适用”或缺资料直接改成承诺 |
| 时效与主体 | 作者/企业身份、版本和更新说明是否真实，过期信息是否影响决策 | 常青事实不要求每年改日期；只有实质更新才改更新时间 |
| 页面结构 | 有HTML时检查语义标题、可读正文、JSON-LD与可见事实一致性 | 检测到不代表平台必引用；静态未检出需渲染复核 |

研究背景来自 [GEO 论文](https://arxiv.org/abs/2311.09735) 对引证、统计、引语和表达方式的实验，以及 [GEO-16 论文](https://arxiv.org/abs/2509.10762) 对页面信号和引用的关联分析。它们提供研究方向，不能证明每个站点的因果效果或把实验涨幅写成客户预期收益。答案优先、短段落等属于编辑建议，并非搜索平台硬性规范。

### 3. 改写时只使用已确认信息

每项建议引用原文片段，定位段落，解释影响，给出可替换文本或明确的资料补齐动作。

- 不编造数字、测试结果、认证、客户、作者、日期、来源或链接。
- 来源未取得时，写“待确认：需要哪份资料/什么测试条件”；不写成已完成事实。不让含占位符的草稿冒充可发布稿。
- 可直接替换的改写只使用输入中已有或本轮查证的事实。需要新增资料时，单独列“待资料后补写”。
- 外部事实引用优先原始论文、官方说明、标准或原始报告，并实际读取支持该断言的内容。
- 只优化与采购任务相关的现有内容。扩展FAQ应来自真实问题，不建议批量生成重复或薄内容。

## 输出

默认中文，尊重用户指定语言和保存位置。使用 Markdown；无文件写入能力时直接在对话交付。

### A. 页面结论与覆盖范围

写明输入方式、页型、目标读者、主要问题、已有优点、实际覆盖段落与未验证项。用“基础清楚 / 需局部改进 / 核心信息待补 / 未验证”描述，不给平台引用概率或官方GEO分。

### B. 段落检查表

| 段落/逻辑块 | 原文定位 | 事实与来源 | 表达与完整性 | 状态 | 建议 |
|---|---|---|---|---|---|

状态用“可保留 / 需改写 / 待资料 / 不适用”。它们是编辑判断，不代表AI必定引用或拒绝引用。信息正确但没有数字的段落可以保留。

### C. 优先改写

选最影响采购理解的3–5处，证据不足就减少。每处提供：

1. 段落编号与原文片段。
2. 问题和对读者的影响。
3. 可直接替换的改写；事实不足时提供保守版本或资料请求。
4. 依据，以及复核方法；不填“预期引用+XX%”。

### D. HTML / Schema（有证据时）

有源码时记录发现的类型、语法问题和与可见正文的冲突。JSON合法不等于满足某个搜索展示规则；只读正文时本节明确“未验证”。

仅在用户需要且真实字段充分时提供 JSON-LD。按页型选择，所有字段须与可见信息相符；不填虚构价格、评分、作者或资质。信息不足则列缺失字段，不输出伪装成可用的代码。不默认添加FAQPage/HowTo，也不承诺富结果。

### E. 下一步

给出一项最小改进与验收方式，例如核实某个参数并替换¶3，或让目标采购人员验证对比表是否足够决策。用户要测平台效果时，另行固定问题、日期和平台，分别记录品牌提及、官网引用与场景推荐，不能拿这份内容审阅代替实测。

## 技术规则查证入口

涉及具体平台要求时核对当时官方资料：

- [Google AI 功能与网站](https://developers.google.com/search/docs/appearance/ai-features)：Google 的适用说明不能外推到全部平台。
- [结构化数据基本说明](https://developers.google.com/search/docs/appearance/structured-data/intro-structured-data) 与 [质量指南](https://developers.google.com/search/docs/appearance/structured-data/sd-policies)。
